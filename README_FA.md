# 🌰 راهنمای جامع سامانه آموزشگاه شیرینی و آشپزی فندق
> **سامانه دو منظوره لندینگ پیج هنرجویان / مشتریان + پنل پیشرفته مدیریت (ادمین)**

این مستند وضعیت موجود کد را توضیح می‌دهد. آخرین بازبینی کد و آزمون محلی: **۲۰۲۶-۱۱-۰۴**.

> **وضعیت فعلی:** رابط کاربری امکانات گسترده‌ای برای نمایش و مدیریت محلی دارد. بک‌اند Express و بخشی از APIها نوشته شده‌اند، اما عملیات اصلی رابط کاربری هنوز به آن‌ها متصل نیست. روشن‌کردن PostgreSQL به‌تنهایی داده‌های سایت را به دیتابیس منتقل نمی‌کند. پروژه در وضعیت فعلی برای بهره‌برداری واقعی چندکاربره آماده نیست.

### پاسخ سریع درباره ذخیره‌سازی

| مسیر استفاده | محل ذخیره فعلی | ماندگاری |
|---|---|---|
| ثبت‌نام، سفارش و تغییرات پنل از داخل سایت | `localStorage` همان مرورگر، چه دیتابیس وصل باشد چه نباشد | با رفرش باقی می‌ماند؛ با پاک‌شدن داده‌های سایت از بین می‌رود |
| درخواست مستقیم به API با PostgreSQL متصل | PostgreSQL، برای عملیات پیاده‌سازی‌شده | مستقل از مرورگر؛ در Docker وابسته به حفظ volume |
| درخواست مستقیم به API بدون PostgreSQL هنگام راه‌اندازی | RAM فرایند Node.js (`inMemoryStore`) | با توقف یا ری‌استارت سرور از بین می‌رود |

مثلاً سفارش ثبت‌شده توسط مشتری در مرورگر گوشی، فعلاً در پنل مدیر روی کامپیوتر دیگری دیده نمی‌شود. انتقال خودکار بین LocalStorage، RAM و PostgreSQL وجود ندارد. جزئیات ذخیره‌سازی و محدودیت‌ها در بخش ۵ و [راهنمای بک‌اند](DOCKER_AND_BACKEND_FA.md) آمده است.

## ۱. پشته فنی و تکنولوژی‌های به‌کار رفته (Tech Stack)

فناوری‌های تعریف‌شده در `package.json` و فایل‌های اجرایی پروژه:

| بخش | تکنولوژی | توضیحات |
| :--- | :--- | :--- |
| **هسته فرانت‌اند** | **React 19** | بر پایه کامپوننت‌های تابعی مدرن (Functional Components) و هوک‌های اختصاصی |
| **هسته بک‌ند و سرور** | **Node.js + Express 4 + tsx** | سرور در `server.ts`، APIهای HTTP و ارائه فرانت‌اند؛ WebSocket یا همگام‌سازی بی‌درنگ ندارد |
| **پایگاه داده رابطه‌ای** | **PostgreSQL 16 در Compose + pg** | ساخت ۸ جدول و اجرای SQL پارامتری؛ عملیات اصلی UI هنوز مصرف‌کننده این لایه نیست |

| **ابزار بیلد و توسعه** | **Vite 8** | ساخت SPA و middleware توسعه داخل Express |
| **طراحی و استایل** | **Tailwind CSS v4** | نسخه ۴ تیلویند با بارگذاری بهینه، طراحی ریسپانسیو اختصاصی موبایل و دسکتاپ |
| **تایپوگرافی فارسی** | **فونت وزیرمتن (Vazirmatn)** | دریافت از Google Fonts و jsDelivr؛ صفحه فارسی و RTL است و دسترسی به فونت وابسته به شبکه است |
| **آیکون‌ها** | **Lucide React** | مجموعه آیکون‌های وکتوری مدرن و سبک |
| **مستندات بک‌ند و داکر** | **DOCKER_AND_BACKEND_FA.md** | مستندات کامل فنی مخصوص استقرار و هوش‌های مصنوعی آینده |

## ۳. ویژگی‌های کلیدی جدید و سازوکار آن‌ها

قابلیت‌های این بخش و بخش ۴ در رابط کاربری و داده‌های همان مرورگر اجرا می‌شوند؛ توصیف آن‌ها به معنی تکمیل API، پرداخت واقعی، ارسال پیامک یا همگام‌سازی بین دستگاه‌ها نیست. جابه‌جایی لندینگ و پنل با state به نام `currentView` انجام می‌شود؛ مسیریاب مستقل در کد وجود ندارد.

### الف) ثبت‌نام چنددوره‌ای و پرونده جامع سوابق هنرجو (Student Multi-Enrollment & Dossier)
پیش از این هر رکورد هنرجو فقط به یک دوره اشاره داشت؛ اما اکنون ساختار داده به گونه‌ای طراحی شده که:
1. **ثبت‌نام در چند دوره هم‌زمان:** یک هنرجو (با یک شماره موبایل و کد ملی) می‌تواند در چندین دوره مختلف شرکت کند (`enrollments: CourseEnrollment[]`). هر دوره دارای اطلاعات اختصاصی زیر است:
   - نام و شناسه دوره
   - تاریخ ثبت‌نام در آن دوره
   - شهریه کل دوره و مبلغ پرداختی (بیعانه / اقساط)
   - وضعیت پرداخت (`paid`، `partial`، `pending`)
   - وضعیت هنرجو در آن دوره (`active`، `graduated`، `reserved`)
   - تیک اختصاصی صدور مدرک بین‌المللی پایان‌دوره (`certificateIssued`)
2. **ثبت‌نام هوشمند بدون داده تکراری:**
   - اگر از دکمه «+ ثبت‌نام جدید» در کنار نام هنرجو استفاده کنید، مستقیماً فرم ثبت‌نام دوره جدید برای همان فرد باز می‌شود.
   - همچنین اگر از فرم اصلی «افزودن هنرجو» استفاده شود و شماره موبایل وارد شده از قبل در سیستم وجود داشته باشد، به جای ایجاد ردیف تکراری، دوره جدید به پرونده سوابق همان هنرجو الصاق می‌گردد.
3. **پرونده و سوابق جامع هنرجو (Dossier Modal):**
   - با کلیک روی آیکون پرونده در جدول، مودال کامل سوابق باز می‌شود:
   - **سوابق دوره‌ها:** مشاهده ریز شهریه‌ها، اقساط باقیمانده، سوییچ صدور مدرک و وضعیت دوره با امکان حذف یا افزودن دوره.
   - **سوابق سفارشات کیک و شیرینی:** سیستم با تطبیق خودکار شماره تماس و نام هنرجو با جدول سفارشات آتلیه، تمام خریدهای قبلی هنرجو (کیک تولد، دسر، شیرینی، مبالغ فاکتور و وضعیت ارسال) را نمایش می‌دهد.
   - **خلاصه مالی و تراز:** محاسبه سرجمع کل شهریه‌ها، کل پرداختی‌ها و مانده طلب آموزشگاه از هنرجو.

---

### ب) شبکه‌های اجتماعی و پیام‌رسان‌های کاملاً داینامیک (Dynamic Social Media Manager)
هیچ‌یک از لینک‌های شبکه‌های اجتماعی در سایت هاردکد نیستند و مدیر سایت می‌تواند در پنل ادمین:
1. **افزودن نامحدود شبکه اجتماعی:**
   - پشتیبانی از پلتفرم‌های پرکاربرد ایرانی و بین‌المللی: **اینستاگرام، تلگرام، ایتا، بله، واتساپ، روبیکا، آپارات، یوتیوب، پینترست، لینکدین، وب‌سایت مستقل و...**
   - فرم اختصاصی شامل: انتخاب پلتفرم، عنوان دلخواه (مثلاً «کانال ایتای هنرجویان»)، شناسه کاربری (Handle) و آدرس اینترنتی کامل (URL).
2. **سوییچ فعال/مخفی آنی (Eye Toggle):**
   - مدیر می‌تواند بدون حذف کردن یک کانال، نمایش آن را در سایت موقتاً خاموش یا روشن کند.
3. **نمایش زنده در فوتر سایت:**
   - در فوتر سایت، نوار ویژه شبکه‌های اجتماعی تعبیه شده که با آیکون‌های وکتوری اختصاصی هر پلتفرم، نام کانال، آیدی کاربری و لینک مستقیم بازشونده در تب جدید نمایش داده می‌شوند.

### ج) مدیریت کلیه متون، هدر، فوتر و لوگو (Site Content Settings)
در تب **«تنظیمات سایت»** در پنل ادمین، ۵ بخش کامل برای کنترل داینامیک وجود دارد:
1. **هدر و نام برند:** تغییر نام آموزشگاه، زیرعنوان برند و آدرس تصویر لوگو.
2. **بخش هیرو (Hero Banner):** ویرایش تیتر اصلی، متن برچسب بالای تیتر، پاراگراف معرفی و انتخاب تصویر بزرگ بالای سایت از بین تصاویر باکیفیت.
3. **آمار کلیدی (KPIs):** ویرایش ۴ باکس افتخارات (تعداد فارغ‌التحصیلان، اعتبار مدرک فنی‌وحرفه‌ای، کارگاه‌های عملی و مدت پشتیبانی).
4. **اطلاعات تماس و فوتر:** تلفن ثابت، شماره همراه مشاوره، آدرس پستی، ساعات کاری، شماره پروانه سازمان فنی‌وحرفه‌ای و متن بیوگرافی فوتر.
5. **ارتباطات آنلاین و واتساپ:** شماره واتساپ مشاوره سفارش کیک، شناسه اصلی اینستاگرام و متن بنر سفارش کیک‌های خاص پینترست.

---

### د) پالت جستجوی سراسری هوشمند (Global Command Palette & Search)
یک ماژول جستجوی سریع و بدون تاخیر در نوار بالای سایت (`Navbar.tsx` و `GlobalSearchModal.tsx`) اضافه شده است که به کاربر اجازه می‌دهد بلافاصله هر آنچه نیاز دارد را بیابد:
1. **دسترسی سریع از هر نقطه سایت:**
   - با کلیک روی فیلد جستجو در نوار بالای سایت (هم نسخه دسکتاپ و هم آیکون جستجو در موبایل).
   - با فشردن کلید میانبر استاندارد بین‌المللی **`Ctrl + K`** (یا **`⌘K`** در مک) از هر جای سایت.
2. **جستجوی عمیق و چندبُعدی (Multi-Facet Search):**
   - **دوره‌های آموزشی:** جستجو در عنوان دوره، توضیحات، نام مدرس، سطح دوره و حتی تک‌تک **سرفصل‌های آموزشی** (مثلاً با سرچ «خمیرترش» یا «فوندانت»).
   - **محصولات، کیک و دسرها:** جستجو در نام کیک، توضیحات، دسته‌بندی و **مواد اولیه و مغزی‌ها** (مثلاً با سرچ «پسته»، «نوتلا» یا «گاناش بلژیکی»).
   - **دسته‌بندی‌های سایت:** جستجو و مشاهده سریع شاخه‌های کیک و دوره‌ها با نمایش تعداد آیتم‌های موجود.
3. **فیلترهای تب‌بندی شده:** امکان فیلتر روی «همه آیتم‌ها»، «دوره‌های آموزشی»، «کیک و دسر» و «دسته‌بندی‌ها».
4. **هایلایت کلمات و ناوبری با کیبورد:** کلمات جستجوشده درون عنوان و توضیحات هایلایت می‌شوند؛ با کلیدهای جهت‌نمای `↑` و `↓` می‌توان بین نتایج حرکت کرد و با کلید `Enter` مستقیم مودال ثبت‌نام یا سفارش محصول را باز کرد.
5. **پیشنهادات داینامیک:** در حالت خالی بودن کادر، جستجوهای پرطرفدار و کلیدواژه‌های پیشنهادی جهت راحتی کاربر نمایش داده می‌شوند.

## ۴. راهنمای استفاده از بخش‌های سایت

### الف) بخش لندینگ پیج (نمای مراجعین، هنرجویان و مشتریان)
1. **مشاهده دوره‌ها:**
   - فیلتر بر اساس دسته‌بندی (کیک‌سازی، دسرهای فرانسوی، شیرینی سنتی، نان حجیم).
   - فیلتر نوع برگزاری (حضوری با کار عملی، نیمه‌خصوصی، آنلاین).
   - نوار پیشرفت ظرفیت به هنرجو نشان می‌دهد چند صندلی خالی باقی مانده است.
   - با کلیک روی **«سرفصل‌ها و ثبت‌نام»**، تمام مهارت‌ها و آیتم‌های تدریسی را دیده و می‌تواند مستقیماً فرم رزرو صندلی را پر کند.
2. **سفارش آنلاین کیک و دسر:**
   - دسته‌بندی‌های داینامیک کیک برای مناسبت‌های مختلف: **تولد، عروسی و نامزدی، دورهمی، پسرانه، دخترانه**.
   - انتخاب وزن (کیلوگرم)، انتخاب مغز و فیلینگ (موز و گردو، نوتلا فندق، تمشک جنگلی، پسته).
   - نوشتن متن اختصاصی روی کیک و تذکرات مربوط به رنگ یا آلرژی.
   - سبد خرید همراه با محاسبه لحظه‌ای مبلغ، دریافت آدرس و صدور کد رهگیری سفارش (مانند `FND-8491`).
3. **مرکز جستجوی پاسخ سوالات (FAQ):**
   - قابلیت سرچ لحظه‌ای در بین سوالات؛ با تایپ عبارت‌هایی چون «مدرک معتبره؟» یا «اقساطی میشه پرداخت کرد؟»، پاسخ مربوطه فوراً فیلتر می‌شود.
4. **سامانه خودکار «پیگیری سفارش و سوابق هنرجو» (Inquiry Portal):**
   - دکمه استعلام در نوار هدر قرار دارد.
   - هنرجو یا مشتری با وارد کردن شماره همراه خود، بدون نیاز به پسورد می‌تواند:
     - دوره‌هایی که در آن‌ها ثبت‌نام کرده و وضعیت صدور مدرک بین‌المللی خود را ببیند.
     - وضعیت سفارشات کیک و دسر خود را (در حال پخت در کارگاه، آماده‌سازی، تحویل) پیگیری کند.
     - با وارد کردن کد رهگیری اختصاصی (مثل `FND-8491`) وضعیت فاکتور و ارسال سفارش را استعلام نماید.

---

### ب) بخش داشبورد مدیریت (پنل ادمین)
برای ورود کافیست روی دکمه **«پنل ادمین فندق»** در نوار بالای سایت کلیک فرمایید:
1. **پیشخوان (Overview):** نمایش آمار کلیدی تعداد هنرجویان، مجموع شهریه تسویه شده، مانده مطالبات اقساط و سفارشات جدید.
2. **مدیریت هنرجویان (Students):** 
   - مشاهده لیست هنرجویان با نشان تعداد دوره‌های ثبت‌نامی و وضعیت تراز مالی.
   - دکمه‌های اقدام سریع: باز کردن پرونده جامع، ثبت‌نام در دوره جدید، ویرایش مشخصات و حذف.
3. **مدیریت دوره‌ها (Courses):** 
   - ویرایش شهریه و تخفیف‌ها.
   - مدیریت داینامیک لیست سرفصل‌ها و آیتم‌های تدریسی (افزودن و حذف تکنیک‌ها).
   - تنظیم ظرفیت کل و شمارش خودکار صندلی‌های باقیمانده.
4. **منوی کیک و شیرینی (Products):**
   - افزودن انواع کیک‌های سفارشی به زیردسته‌های تولد، عروسی، پسرانه، دخترانه، دسرها و شیرینی خشک.
   - قیمت‌گذاری به ازای هر کیلوگرم یا به ازای بسته.
   - تعیین زمان آماده‌سازی کارگاهی (Lead Time).
5. **سفارشات مشتریان (Orders):**
   - مشاهده سفارشاتی که از طریق سایت ثبت شده‌اند.
   - بررسی متن روی کیک، طعم فیلینگ، تاریخ و آدرس تحویل.
   - تغییر وضعیت به: *در انتظار تایید ← در حال آماده‌سازی کارگاهی ← آماده تحویل ← تحویل داده شد*.
6. **تنظیمات محتوایی سایت (Site Settings):**
   - مدیریت هدر، لوگو، هیرو، آمارها، اطلاعات تماس و شبکه‌های اجتماعی داینامیک.
7. **پشتیبان‌گیری و پایگاه داده (Settings):**
   - **دانلود فایل Backup JSON:** دریافت فایل از کلیه اطلاعات (شامل دوره‌ها، هنرجوها، محصولات، سفارشات و تنظیمات هدر/فوتر) با یک کلیک.
   - **بازیابی از فایل JSON:** بازگردانی اطلاعات ذخیره‌شده قبلی روی هر مرورگر یا سیستم دیگر.
   - **بازنشانی داده‌ها:** بازگشت به اطلاعات نمونه استاندارد آموزشگاه در صورت نیاز.

## ۵. جریان داده و ماندگاری اطلاعات

### مسیر واقعی رابط کاربری

```text
main.tsx → App.tsx → AppProvider / AppContext
                         ├─ LandingPage و مودال‌های ثبت‌نام، سفارش و استعلام
                         └─ AdminDashboard و مدیرهای هر بخش

عملیات هر دو نما → state ری‌اکت → localStorage مرورگر
ورود مدیر و بررسی سلامت → apiClient → Express /api
درخواست مستقیم به سایر APIها → PostgreSQL یا RAM سرور
```

`AppContext.tsx` داده‌ها را از LocalStorage می‌خواند و در نبود داده یا خطای خواندن JSON، از `initialData.ts` استفاده می‌کند. تغییرات state با `useEffect` در کلیدهای زیر نوشته می‌شوند:

| داده | کلید LocalStorage |
|---|---|
| تنظیمات سایت | `fandoq_site_settings_v1` |
| دوره‌ها | `fandoq_courses_v1` |
| هنرجویان و ثبت‌نام‌هایشان | `fandoq_students_v1` |
| محصولات | `fandoq_products_v1` |
| سفارشات | `fandoq_orders_v1` |
| پرسش‌های متداول | `fandoq_faqs_v1` |
| سبد خرید | `fandoq_cart_v1` |

- اطلاعات به مرورگر/پروفایل و مبدأ سایت وابسته‌اند؛ تغییر دامنه، پروتکل یا پورت، فضای ذخیره‌سازی جدا ایجاد می‌کند. مثلاً `localhost` و `127.0.0.1` داده مشترک ندارند.
- رفرش و بستن عادی مرورگر معمولاً داده را حذف نمی‌کند؛ پاک‌کردن داده سایت یا پایان نشست خصوصی می‌تواند آن را حذف کند. خطای پرشدن ظرفیت یا ممنوع‌بودن نوشتن LocalStorage در اثرهای ذخیره‌سازی مدیریت نشده است.
- سفارش و ثبت‌نام محلی به مدیر روی دستگاه دیگر ارسال نمی‌شود؛ استعلام هم فقط داده‌های همان مرورگر را جستجو می‌کند.
- رویداد `storage` برای همگام‌سازی state تب‌های باز پیاده‌سازی نشده است؛ تغییرات هم‌زمان ممکن است همدیگر را بازنویسی کنند.
- SQLite، ذخیره خودکار در فایل محلی سرور، صف آفلاین، انتقال خودکار به PostgreSQL و حل تعارض وجود ندارد. نبود دیتابیس با پشتیبانی کامل از اجرای آفلاین یکسان نیست؛ Service Worker نیز پیاده‌سازی نشده است.

### پشتیبان و بازیابی

در پنل «پشتیبان‌گیری و دیتابیس»، خروجی JSON شامل `siteSettings`، `courses`، `students`، `products`، `orders`، `faqs` و زمان خروجی است. **سبد خرید، حساب‌های مدیر و توکن ورود در خروجی نیستند.** این فایل پشتیبان PostgreSQL محسوب نمی‌شود.

بازیابی فقط داده‌های مرورگر را جایگزین می‌کند؛ به API چیزی نمی‌فرستد. اعتبارسنجی آن در حد parse کردن JSON و وجود فیلدهاست، بنابراین فایل ناسازگار ممکن است UI را دچار خطا کند. بازنشانی نیز فقط داده‌های محلی را به نمونه‌ها برمی‌گرداند.

### وضعیت بک‌اند و کارهای باقی‌مانده

بک‌اند قابل اجراست و مسیرهایی برای احراز هویت، تنظیمات، دوره‌ها، هنرجویان، ثبت‌نام، محصولات، سفارش و استعلام دارد. اما برای استفاده واقعی این کارها لازم‌اند:

1. تکمیل API ویرایش دوره/هنرجو/ثبت‌نام، حذف ثبت‌نام، مدیریت محصولات و FAQ، تغییر وضعیت و حذف سفارش، و ثبت‌نام عمومی هنرجو.
2. اتصال تمام عملیات `AppContext`، ثبت سفارش و استعلام به API همراه با نمایش خطای ذخیره و وضعیت بارگذاری. قرارداد پاسخ‌ها شیء پوششی مانند `{ success, students }` است؛ مسیر ثبت‌نام موجود `/api/students/:id/enroll` است، نه `/enrollments`.
3. حذف ورود نمایشی: اکنون بعد از شکست درخواست ورود، نام کاربری `admin` با رمزهای نمایشی پذیرفته می‌شود و توکن جعلی ساخته می‌شود. وجود هر رشته توکن نیز برای نمایش پنل کافی است؛ API محافظت‌شده همچنان JWT واقعی می‌خواهد.
4. اعتبارسنجی ورودی، کنترل ظرفیت و ثبت‌نام تکراری، تراکنش برای ثبت هنرجو و دوره، محاسبه مبلغ سفارش در سرور و محدودکردن استعلام اطلاعات شخصی.
5. تعیین سیاست صریح قطع دیتابیس؛ RAM فعلی ذخیره پایدار نیست و همگام‌سازی یا بازیابی خودکار داده ندارد.
6. اصلاح مسیر تصاویر Production و آزمون واقعی PostgreSQL، Docker، ماندگاری داده و گردش کار چندکاربره.

درگاه پرداخت، پیامک/OTP و تولید فایل گواهی به سرویس واقعی متصل نیستند؛ وضعیت پرداخت و صدور مدرک فعلاً فیلدهای داده‌اند. جزئیات API و ایرادهای شناخته‌شده در [DOCKER_AND_BACKEND_FA.md](DOCKER_AND_BACKEND_FA.md) ثبت شده است.

## ۶. راه‌اندازی و دستورات اجرایی

Dockerfile از Node.js 22 استفاده می‌کند. در بازبینی حاضر وابستگی‌های موجود با Node.js `23.11.1` بررسی شدند؛ نصب تازه وابستگی‌ها آزمایش نشده است.

```powershell
npm install
# فقط در صورت نبود .env؛ فایل تنظیمات موجود را بازنویسی نکنید
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm run dev
```

سایت و API به‌صورت پیش‌فرض روی `http://localhost:3000` اجرا می‌شوند. برای PostgreSQL روی خود سیستم، `POSTGRES_HOST=localhost` تنظیم شود؛ مقدار `postgres` در فایل نمونه مربوط به شبکه Compose است. بدون دیتابیس هم سرور با RAM راه می‌افتد و UI همچنان محلی کار می‌کند.

| دستور | کار واقعی |
|---|---|
| `npm run dev` | اجرای `tsx server.ts` با Vite middleware در محیط توسعه؛ watch مستقل سرور تعریف نشده است |
| `npm run lint` | فقط `tsc --noEmit`؛ ESLint یا تست رفتاری نیست |
| `npm run build` | ساخت فرانت‌اند در `dist`؛ بک‌اند را باندل یا type-check نمی‌کند |
| `npm start` | همان `tsx server.ts`؛ محیط اجرا را مقدار `NODE_ENV` تعیین می‌کند |
| `npm run preview` | پیش‌نمایش فرانت‌اند با Vite؛ Express و API را اجرا نمی‌کند |
| `npm run clean` | دستور `rm -rf` وابسته به شل Unix؛ در شل پیش‌فرض ویندوز قابل اتکا نیست |

برای بررسی خروجی Production در PowerShell، پس از build:

```powershell
$env:NODE_ENV = 'production'
npm start
# برای برگشت به توسعه در همین ترمینال: $env:NODE_ENV = 'development'
```

## ۷. نتیجه بررسی در ۲۰۲۶-۱۱-۰۴

- `npm run lint`: موفق.
- `npm run build`: موفق؛ هشدار استفاده از `__dirname` در تنظیمات Vite و حجم chunk جاوااسکریپت حدود ۵۰۲ کیلوبایت وجود دارد.
- آزمون HTTP در فرایند موقت با دیتابیس عمداً ناموجود: اجرای سرور Production، سلامت با `in_memory_fallback`، پاسخ ۴۰۱ مسیر خصوصی بدون توکن، ورود واقعی API، بررسی JWT و ثبت/خواندن سفارش موفق بود. سفارش آزمایشی پس از ری‌استارت حذف شد.
- درخواست تصویر نمونه `/src/assets/images/product_wedding_cake_1793696673644.jpg` در Production به‌جای تصویر، `text/html` دریافت کرد. تصاویر با مسیر رشته‌ای `/src/assets/...` به `dist` منتقل نشده‌اند؛ موفقیت build تضمین نمایش تصاویر نیست.
- Docker CLI موجود بود اما daemon اجرا نبود؛ آزمون یکپارچه PostgreSQL و ساخت/اجرای کانتینر انجام نشد. آزمون بصری مرورگر نیز در این بازبینی انجام نشد.

در این بازبینی مستندات اصلاح شدند؛ موارد نیازمند تغییر کد در بالا فهرست شده‌اند و هنوز رفع نشده‌اند.
